# Tvijo DSHREM — ממשימה לתוצאה בדוקה

[English](README.en.md) · [Русский](README.ru.md) · [All languages / Все языки](../../README.md#read-the-introductory-guide-in-your-language)

Tvijo מביאה יחד סביבת עבודה בדפדפן, תוסף VS Code וכלי טרמינל סביב זרימת פיתוח משותפת. תארו את המשימה, בחרו את מארח ההרצה ואת ההרשאות שלה, עיינו בשינויים, ושמרו את הראיות שבאמצעותן אושרה התוצאה. מדריך זה מציג את המוצר; ה-README הטכני של המאגר ומדריך הפקודות נשארים הסמכות הקובעת עבור ה-CLI.

## מתחילים מסביבת העבודה המועדפת עליכם

פתחו את [DSHREM](https://dsh.tvijo.com/), קבלו את [תוסף VS Code והוראות הטרמינל](https://dsh.tvijo.com/download), או קראו את [ההסבר על ההגדרות](https://dsh.tvijo.com/knowledge/settings-explained). התחברו דרך זרימת החשבון הנתמכת של השירות. לעולם אל תדביקו מפתחות API של ספקים בתוך פרומפט משותף, ב-issue ציבורי או במאגר.

ה-CLI של Node.js דורש Node 22 או גרסה חדשה יותר. מתוך עותק מקומי של המאגר:

```sh
npm install -g .
dsh login
dsh doctor
dsh chat
```

הפקודה זמינה גם בשם `dshrem`. ה-CLI הזה של צ'אט מרחוק מציג כלים מוצעים בלי להריץ אותם. עריכה מקומית והרצת פקודות שייכות ל-VS Code Agent או ל-runtime של מארח שהוגדר במפורש; יש להן הרשאות נפרדות. ראו [עזרה ל-CLI](https://github.com/nikbibamon/dshrempub/blob/main/docs/HELP.md).

## להבין את האפשרויות

**קודם ראיות** מפריד בין עובדות מבוססות לבין הנחות. **תכנון ובדיקה** מבקש תוכנית קצרה ובודק את התוצאה מול הבקשה. **סקירת התשובה** מאתגרת טיוטה; זהו סקירה עצמית אלא אם כן הוקצה במפורש סוקר נפרד. אף אחת מהשיטות הללו אינה מבטיחה נכונות או שימוש מופחת בטוקנים.

פריסטים של משימות מוסיפים הוראות ורשימות בדיקה לשימוש חוזר. הם אינם יוצרים זיכרון מודל נוסף. אוסף הקשר גדול יותר עדיין חייב להתאים למגבלות הבקשה של השירות ושל המודל. נתיבי controller, Python ו-state מתקדמים מתייחסים למארח התוסף שנבחר; ב-Remote SSH זהו השרת המרוחק.

## לעבוד בצוות כשזה עוזר

צוות AGENTROY מקצה ל-coordinator, ל-implementers ולסוקרים אחריות נפרדת. מדיניות המארח עשויה לבקש את DSHREM ds41f ואת כלי Codex או Claude המבוססים על חשבון, עם סקירה ארכיטקטונית אופציונלית. הזמינות תלויה ב-runtime המותקן, בגישה לחשבון ובמדיניות שנבחרה. מנוי חסר אסור שיהפוך בשקט לקריאת API בתשלום.

שלושה עד שישה תפקידים הם בחירות ארגוניות, לא נוסחה לאיכות. סוקרים זקוקים לגרסה המדויקת של התוצר ולראיות הבדיקה. בדיקה שנכשלה באופן מהותי חוסמת אישור גם כשהמודלים מסכימים. קראו את [צוותי סוכנים ועלויות גלויות](https://dsh.tvijo.com/knowledge/agentroy-teams-and-costs).

## לחדש עבודה בלי להסתיר אי-ודאות

סשן tmux מנותק בצד השרת יכול להמשיך לאחר שמחשב נייד או טלפון מתנתקים. עבודה על מחשב מקומי כבוי אינה יכולה. כשל שרת, לחץ על הזיכרון ואובדן אחסון עדיין דורשים התאוששות. התחברו מחדש למזהה המשימה השמור ובחנו את האירוע המאושר האחרון שלה לפני שמתחילים עבודה נוספת. אל תחזרו באופן עיוור על בקשה מחייבת שתוצאתה אינה ידועה. ראו [ניתוקים והתאוששות](https://dsh.tvijo.com/knowledge/durable-work-and-recovery).

## לשמור על עלויות ונתונים גלויים

עיינו בהצעת המחיר שאושרה, בתקרת המשימה, בסכום השמור ובקבלה על השימוש. תוספת שירות של 8% הייתה הופכת שימוש של USD1.00 אצל הספק ל-USD1.08 לפני חיובים שנמסרים בנפרד; זו דוגמה, לא הצעת מחיר. מכסות מנוי, חיובי ספקים ומשאבי שרת הם מגבלות שונות. תקציב נוסף דורש בחירה מפורשת.

קובצי אישורים של ה-CLI המקומי משתמשים בהרשאות של בעלים בלבד. הרשאות אלו אינן הצפנה או גיבוי. העלאת ידע היא מפורשת; קבצים פרטיים לעולם לא צריכים להיכנס לקישור מסירה ציבורי. [מסירות פרומפט](https://dsh.tvijo.com/knowledge/prompt-handoffs) מסבירות כיצד להעביר משימה שנסקרה לכלי אחר.

החבילה של מאגר זה מסומנת כיום כ-`UNLICENSED`; פרסום אינו מעניק זכויות שימוש חוזר. עיינו במטא-נתוני החבילה ובהצהרת הרישוי העדכניים לפני הפצה מחדש. תרגומים הם מדריכי מבוא, שנוצרים עם DSHREM ונבדקים לעקביות מבנית; האנגלית היא ההתייחסות לסתירות טכניות.
