# 0.10.2 — sign-in and preview context repair

Copy code keeps the same device challenge open with its browser approval action. Cancelling stops authorization. The initial account label asks for sign-in instead of asserting a free plan; verified accounts keep their real remaining limits.

Automatically generated project context uses a smaller preview bound. User questions, explicit selections and attachments are preserved. Known context refusals and uncertain-charge errors have fixed safe messages; the client does not retry paid requests.

The companion gateway patch distinguishes a preview context refusal before the first dispatch from unknown provider spend after dispatch. Only the former becomes a terminal refusal with a released local reservation.

Verification: 596 extension checks, 20 gateway/trial/failover checks, and two rendered synthetic-host Chromium viewport cases. Native VS Code sign-in dialog integration is not independently runtime-tested; its action and cancellation behavior has unit coverage. Production provider and installed-package receipts remain separate artifacts.
