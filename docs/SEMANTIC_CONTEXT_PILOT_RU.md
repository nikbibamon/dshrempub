# Пилот outline активного документа, 2026-10-25

Реализован один ограниченный P0-пилот: существующий collector контекста может заменить блок активного исходника компактным outline через `vscode.executeDocumentSymbolProvider`. Это только outline активного документа. Индекс, сервер, зависимости, definition/reference navigation и редактирование символов не добавлены.

Основа: чистая ветка `perf/unified-upgrade-ext-fd0e8bd8`, HEAD `155bde788c1fb72b2d36511de1f44a92745ed687`, расширение `0.10.11`. Версия сохранена. Оригинальный AIOS и его governance не изменялись; исходный HARD_RED остаётся. Этот checkpoint требует независимого review supervisor и не является общей приёмкой unified upgrade.

## Включение и откат

Новая настройка `tvijo.semanticContext` имеет тип boolean, scope resource и default `false`. Для локального эксперимента пользователь может включить её в настройках разрешённого проекта:

```json
{
  "tvijo.semanticContext": true
}
```

Collector сам читает настройку для URI документа: существующие вызовы из chat, agent, preview и `rules-host` не переписаны. Для отката достаточно `"tvijo.semanticContext": false`; исходный блок снова собирается прежним способом. Удалять файлы или откатывать чужие изменения для этого не требуется. При выключенном флаге вывод совместим с прежним collector; проверена идентичность текста и summary.

## Допуск и ограничения

Provider вызывается только для документа, допущенного к существующему блоку активного исходника. Учитываются выбранная папка и её текущая валидность, selectedPaths/selectionForFolder, исключённые каталоги, credential-пути и rules-файлы. Требуются явно trusted workspace, `contextMode != off` и настройка `workspaceContext != off`. Для отдельного selectionText outline не собирается: разрешение на выделение не расширяется на весь документ.

Допускается существующий локальный regular file внутри выбранного root. File URI должен иметь пустые authority/query/fragment. Реальный путь root и документа проверяется до provider и после ожидания; каждый компонент внутри root проверяется через lstat. Symlink файла, родительской директории или алиас root исключает outline. Для виртуальных, отсутствующих, внешних и неподтверждённых файлов provider не вызывается. Это намеренно консервативный локальный пилот.

Перед dispatch сканируется полный текст активного документа, а не первые 12 000 символов: переиспользованы `checkKnowledgeFile`, credential-token фильтр и переданные knownSecrets. Дополнительно распознаются токены, встроенные в идентификаторы. Текст более 512 KiB, бинарный/невалидный UTF-8 и секреты запрещают dispatch. При отказе этого сканирования во включённом пилоте активный исходный блок также пропускается: небезопасный текст не возвращается через fallback. Счётчик `skippedSensitive` отражает такой отказ. Метод `document.getText` не заменяется и не модифицируется.

Имена символов отдельно проверяются тем же secret-фильтром и knownSecrets, включая токены внутри имени. Имена с управляющими/направляющими Unicode-символами, пустые или длиннее 512 UTF-8 байт отбрасываются целиком. Не выводятся provider detail/containerName, URI и другие произвольные поля. Распознавание секретов остаётся эвристическим и наследует политику knownSecrets существующего collector, включая минимальную длину 4 символа.

`DocumentSymbol` использует source range; `SymbolInformation` дополнительно обязан указывать тот же нормализованный локальный URI. Другой файл, authority, scheme, query/fragment или отсутствующий location URI отбрасывается. Проверяются вид символа и корректность range относительно lineCount. Строки выводятся явно, начиная с 1, например `Function L1-6: transform0`.

Лимиты: максимум 64 символа, 4 уровня, 256 посещённых записей provider, 4096 UTF-8 байт вместе с заголовком. Используется меньший из этого лимита и оставшегося бюджета collector с резервом для завершающего маркера. В вывод попадают только целые строки; UTF-8 не режется. Итеративный обход и WeakSet ограничивают вложенные/циклические результаты. Заголовок указывает `bounded data`, поэтому outline не заявлен как полный перечень.

Ожидание provider ограничено таймером 200 ms, затем прежний допустимый исходный блок остаётся fallback. Отсутствие команды/provider, исключение, rejection, пустой и некорректный ответ обрабатываются без падения collector. Поздний rejection обработан. Команда VS Code не предоставляет этому вызову cancellation token: timeout прекращает ожидание, но не гарантирует остановку чужого provider; синхронную блокировку event loop таймер прервать не может.

После await повторно проверяются version и URI документа, включая исходное написание URI, trust, настройка, выбранные пути/root и файловый путь. Устаревший outline не принимается. Это проверка снимка и пути, а не атомарная filesystem capability: внешние изменения после последней проверки полностью исключить нельзя. Политика остальных прежних блоков collector остаётся прежней; пилот не заявляет исправление всех legacy context-путей.
